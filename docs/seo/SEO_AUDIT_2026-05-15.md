## 1. Crawlability & Indexation

### 1.1 robots.txt — ✅ ИСПРАВЛЕНО
**Было:** `curl https://ai-photobot.ru/robots.txt → пустой ответ`.
**Стало:** файл `landing/robots.txt` создан и задеплоен в `/var/www/landing/robots.txt`:
```
User-agent: *
Allow: /
Disallow: /dash/

Sitemap: https://ai-photobot.ru/sitemap.xml
```

### 1.2 sitemap.xml — ✅ ИСПРАВЛЕНО
**Было:** `curl -I https://ai-photobot.ru/sitemap.xml → HTTP/2 404`.
**Стало:** добавлен скрипт `scripts/gen_sitemap.py`, который:
- читает лендинг (`/`), блог-индекс (`/blog/`) и все статьи с `published: true` из `blog/posts/*.md`;
- пишет `sitemap.xml` с `<loc>`, `<lastmod>`, `<changefreq>`, `<priority>` для каждого URL.

Hooked в `blog/build.py::local_deploy()` — авто-обновляется на каждой cron-публикации статьи. **Текущий sitemap содержит 53 URL (лендинг + блог-индекс + 51 опубликованная статья).** Подан в Яндекс.Вебмастер и Google Search Console пользователем 2026-05-15.

### 1.3 Crawl-budget — ОК
Сайт маленький (~55 URLs), нет faceted-navigation, нет параметров. Никаких проблем не ожидается.

### 1.4 Canonical — ✅ ИСПРАВЛЕНО
- **Лендинг (`/`):** ✅ добавлен `<link rel="canonical" href="https://ai-photobot.ru/">`.
- **Блог index (`/blog/`):** ✅ был, остался.
- **Блог-статьи:** ✅ self-referencing, остался.
- **www vs non-www:** ✅ ИСПРАВЛЕНО. В Caddyfile разделены блоки: `www.ai-photobot.ru` → `redir https://ai-photobot.ru{uri} permanent`. Проверено: `curl -I https://www.ai-photobot.ru/` → `HTTP/2 301, location: https://ai-photobot.ru/`.

### 1.5 HTTPS / Security — ОК
- HTTPS работает, HTTP/2, HTTP/3 (alt-svc).
- HSTS-заголовок отсутствует — bonus, не критично.
- Mixed content не обнаружен.

- 🟡 **Inline CSS** в каждом блог-HTML файле (~30-40 KB на статью × 51 = ~2 MB избыточности). Не сделано в Phase 1 — отложено в Phase 5 (blog infra).
- ⏳ **Font loading:** не оптимизирован subset, не self-hosted — Phase 6.
- ✅ **Lazy loading:** showcase картинки `loading="lazy"`.
- 🟡 **Width/height** на images: всё ещё отсутствует (CLS-риск). Отложено в Phase 6.
- ✅ **Compression:** Caddy `encode zstd gzip` (`brotli` не включали — `xcaddy` плагин не установлен, zstd даёт сопоставимое сжатие).
- ✅ **Cache headers:** `Cache-Control: public, max-age=31536000, immutable` для `*.css *.js *.png *.jpg *.jpeg *.webp *.gif *.svg *.ico *.woff *.woff2 *.ttf`. Sitemap/robots — `max-age=3600`. Проверено: `curl -sI https://ai-photobot.ru/photo/hero-after.jpg` → `cache-control: public, max-age=31536000, immutable`.

**Что осталось (Phase 5-6):**
1. Заменить background-image hero на `<img>` + `fetchpriority="high"` + `width/height`.
2. Добавить `width/height` атрибуты ко всем `<img>`.
3. Извлечь общий CSS блога в `/blog/style.css` — уменьшит каждый HTML на ~30 KB → быстрее TTFB, лучше кеш.

- Нет персон/use-case секций по профессиям (IT, бухгалтер, учитель — у тебя уже есть блог-статьи на эти темы, можно сделать spoke-pages).
- Нет блока "Отзывы реальных пользователей" — критично для E-E-A-T.

### 6.2 Блог
**Сильные стороны:**
- 52 опубликованные статьи — отличный база-объём.
- SEO-friendly URL slugs ✅
- Frontmatter с meta/description ✅

**Слабые стороны:**
- Автогенерация → риск scaled content abuse policy от Google (требование от 2024 — AI-контент должен быть `useful, original, satisfying`). Нужно периодически качество ручным review.
- **Нет автора** у статей — критично для E-E-A-T в RU YMYL-adjacent темах (карьера/деньги).
- **Нет "Обновлено"** дат → Google понижает свежесть.
- Объём — около 550-600 слов на статью (по WebFetch). Для конкурентных запросов мало; для лонгтейла — норм.
- **Нет картинок внутри статей** — кратно понижает время на странице и шансы попасть в Google Images.
- **Нет внутренних ссылок** между статьями — упущенный SEO/UX bonus.
- **Нет TOC** (оглавления) на длинных статьях — упускаем jump-to-section в SERP.
