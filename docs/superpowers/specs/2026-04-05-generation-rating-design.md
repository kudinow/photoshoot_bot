# Оценка генераций — дизайн

**Дата:** 2026-04-05
**Статус:** утверждён к реализации

## Цель

Собирать качественный фидбек о результатах генерации: понимать, что именно не нравится пользователям, и иметь возможность улучшать промпты/пайплайн. Параллельно — использовать момент положительной оценки (5 звёзд) как эмоциональный триггер для продвижения реферальной программы.

## Поведение

### Когда показывается запрос оценки

Только **один раз в жизни пользователя** — сразу после его самой первой успешной генерации. Для последующих генераций (включая регенерации и новые фото) запрос не появляется.

Критерий первой генерации — уже существующий флаг `was_first_generation`, возвращаемый из `increment_generations()` в `bot/handlers/photo.py` и в хендлере регенерации `bot/handlers/start.py`.

Дополнительная защита от повторного показа — флаг `users.has_rated` в БД. Он выставляется в `1` при любом ответе пользователя (оценка + текст, оценка + Skip, и даже клик по одной из звёзд без последующего текста). Если юзер получил запрос оценки и проигнорировал его, повторного показа не будет.

### Шаг 1. Запрос оценки

Сразу после отправки сообщения с результатом генерации (того самого, где фото с caption и клавиатурой `get_restart_keyboard`), бот отправляет **второе сообщение**:

> Как тебе результат?
>
> [⭐] [⭐] [⭐] [⭐] [⭐]

Пять инлайн-кнопок со звёздочками, `callback_data = rate:1`..`rate:5`.

### Шаг 2а. Юзер ставит 5 звёзд

Сообщение редактируется на:

> 🎉 Рад, что понравилось!
>
> Поделись ботом с другом — и получишь бесплатную генерацию за его первое фото.
>
> [🎁 Получить реферальную ссылку]

Кнопка использует существующий `callback_data = "referral_link"`. Хендлер `show_referral_link` в [bot/handlers/start.py](bot/handlers/start.py) уже существует и отрабатывает этот callback — никакого нового кода для рефералки не требуется.

Админу ничего не отправляется.

Ставится `has_rated = 1`.

### Шаг 2б. Юзер ставит 1–4 звезды

Сообщение редактируется на:

> Жаль, что не идеально 😔
>
> Расскажи, что можно улучшить? Напиши в ответ или нажми «Пропустить».
>
> [Пропустить]

FSM переходит в новое состояние `GenerationStates.awaiting_feedback_text`.

**Одновременно** (не дожидаясь текстового ответа) админу уходят два сообщения:
1. Оригинальное фото пользователя (то, что он загрузил), caption:
   ```
   ⭐ Новая оценка: N/5
   User: <user_id> (@username) <first_name>
   Пол: <мужской|женский>, стиль: <деловой|кежуал|креативный>
   ```
2. Сгенерированное фото, caption: `Результат генерации`

Ставится `has_rated = 1`.

### Шаг 3. Текст фидбека или пропуск

В состоянии `awaiting_feedback_text`:

- **Юзер пишет текст** → бот отвечает *"Спасибо за фидбек! Мы это учтём."*, админу уходит третье сообщение: `Фидбек: <текст>`. FSM очищается.
- **Юзер нажимает Skip** → бот отвечает *"Ок, спасибо за оценку!"*. Админу ничего дополнительно не уходит (у него уже есть оценка с первого этапа). FSM очищается.
- **Юзер присылает фото/стикер/любой не-текст** → игнорируется. Хендлер awaiting_feedback_text слушает только `content_types=[ContentType.TEXT]`.
- **Юзер перезапускает бота через `/start`** → FSM состояние теряется (MemoryStorage). Текстовый фидбек никогда не дойдёт, но админ уже получил оценку и оба фото на первом этапе — потеря минимальна.

## Архитектура

### Новый модуль: `bot/handlers/rating.py`

Новый router, регистрируется в `bot/main.py` после существующих роутеров. Содержит:

- `router = Router()`
- Функция `send_rating_request(bot, chat_id)` — публичная, вызывается из `photo.py` и `start.py` после отправки результата первой генерации.
- `@router.callback_query(F.data.startswith("rate:"))` — обработчик клика по звезде. Парсит оценку, вызывает `mark_as_rated`, отправляет админу оригинал+результат (через `_send_rating_to_admin_stage1`), редактирует сообщение на шаг 2а или 2б, ставит FSM состояние при низкой оценке.
- `@router.message(GenerationStates.awaiting_feedback_text, F.text)` — обработчик текстового фидбека. Отправляет админу через `_send_feedback_text_to_admin`, отвечает юзеру, чистит FSM.
- `@router.callback_query(F.data == "feedback_skip", GenerationStates.awaiting_feedback_text)` — обработчик Skip. Отвечает юзеру, чистит FSM.
- Приватные функции `_send_rating_to_admin_stage1(bot, user, rating)` и `_send_feedback_text_to_admin(bot, user_id, feedback_text)` — собирают данные из БД (file_id/URL оригинала, URL результата, пол, стиль), обращаются к `ADMIN_ID` из `bot/services/user_limits.py`.

### Изменения в `bot/services/user_limits.py`

**Новые колонки в таблице `users` (миграция в `init_db()` через `ALTER TABLE ... ADD COLUMN`, по существующему паттерну):**

- `last_photo_file_id TEXT` — Telegram file_id оригинального фото. Добавляется как отдельная колонка, а не переиспользует `last_photo_url`. Причина: `last_photo_url` сейчас содержит временный Telegram file URL (получаемый через `bot.get_file()`), который протухает через ~1 час и не годится для отправки админу спустя произвольное время. File_id же вечный и работает при передаче в `bot.send_photo(..., photo=file_id)`. Разделение колонок также сохраняет семантику `last_photo_url` для существующей логики регенерации (которая передаёт URL в kie.ai).
- `last_result_url TEXT` — URL сгенерированного результата из kie.ai. Сейчас не сохраняется нигде; нужен для форварда админу.
- `has_rated INTEGER NOT NULL DEFAULT 0` — флаг "уже оценивал когда-то".

**Новые функции:**

- `save_last_photo(user_id, photo_url, photo_file_id, gender, style, result_url)` — расширение существующей функции. Сохраняет все пять полей одним UPDATE. Существующий параметр `photo_url` сохраняется (для регенерации), добавляются `photo_file_id` и `result_url`.
- `mark_as_rated(user_id)` — ставит `has_rated = 1`.
- `has_user_rated(user_id) -> bool` — читает флаг.
- `get_last_generation_context(user_id) -> dict | None` — возвращает `{photo_file_id, result_url, gender, style}` для отправки админу.

**Изменяемая функция:**

- `save_last_photo()` — сигнатура расширяется. Все существующие вызовы (в `photo.py` и `start.py` в ветке регенерации) обновляются.

### Изменения в `bot/handlers/photo.py`

В основном хендлере загрузки фото, после успешной генерации:

1. `save_last_photo(user_id, file_url, photo_file_id, gender, style, result_url)` — добавляется `photo_file_id` (берётся из `message.photo[-1].file_id` в том же хендлере) и `result_url` (из ответа `kie_client.transform_image`). Существующий `file_url` (Telegram file URL) продолжает сохраняться как раньше, для логики регенерации.
2. После отправки результата и реферальной награды, но перед `state.clear()`:
   ```python
   if was_first_generation and not has_user_rated(user_id):
       await send_rating_request(message.bot, message.chat.id)
   ```
3. `state.clear()` по-прежнему вызывается — состояние `awaiting_feedback_text` выставляется позже, из callback-хендлера звёздочек, где у нас есть свежий FSMContext.

### Изменения в `bot/handlers/start.py` (regenerate handler)

Аналогичные изменения в ветке регенерации: если `was_first_generation and not has_user_rated` — вызвать `send_rating_request`. Этот случай редкий (первая генерация через regenerate возможна, только если предыдущая генерация не прошла и юзер жмёт "Сгенерировать заново" без нового фото), но симметричность важна.

### Изменения в `bot/keyboards/inline.py`

Две новые функции:

- `get_rating_keyboard() -> InlineKeyboardMarkup` — один ряд из пяти кнопок `⭐`..`⭐` с callback_data `rate:1`..`rate:5`.
- `get_feedback_skip_keyboard() -> InlineKeyboardMarkup` — одна кнопка "Пропустить" с callback_data `feedback_skip`.
- `get_five_star_keyboard() -> InlineKeyboardMarkup` — одна кнопка "🎁 Получить реферальную ссылку" с callback_data `referral_link` (переиспользует существующий хендлер).

### Изменения в `bot/states/generation.py`

Добавить новое состояние в enum `GenerationStates`:

```python
awaiting_feedback_text = State()
```

### Изменения в `bot/main.py`

Импорт и регистрация нового роутера:

```python
from bot.handlers import rating
dp.include_router(rating.router)
```

## Что в скоупе, а что НЕ в скоупе

**В скоупе:**
- Запрос оценки только после первой генерации
- Форвард низких оценок админу (двухэтапный: оценка+фото сразу, текст позже)
- Кнопка реферальной ссылки при 5 звёздах (переиспользует существующий хендлер `referral_link`)
- Миграция БД (новые колонки через `ALTER TABLE`)

**НЕ в скоупе:**
- Хранение оценок в отдельной таблице и аналитика (явно отвергнуто пользователем — только логи и форвард админу)
- Показ запроса оценки после каждой/N-й генерации
- Структурированные причины низкой оценки (кнопки "лицо не похоже", "плохое качество" и т.д.)
- Дашборд/графики по оценкам
- Уведомление админа о 5-звёздных оценках
- Повторный запрос оценки, если юзер проигнорировал первый (достаточно одного шанса)
- Остальные реферальные touchpoint'ы (#2 после оплаты, #4 команда `/invite`) — остаются в бэклоге

## Edge cases

| Ситуация | Обработка |
|---|---|
| Юзер игнорит запрос оценки и делает новую генерацию | Запрос больше не появится (следующая генерация уже не первая, плюс `has_rated` не выставлен, но проверка `was_first_generation` его не пропустит) |
| Юзер ставит звезду и перезапускает бота до текстового фидбека | Оценка + фото уже у админа (первый этап). Текстовый фидбек теряется. Приемлемо. |
| Юзер в состоянии `awaiting_feedback_text` присылает фото | Игнорируется (хендлер слушает только `F.text`). Старый `photo.py` хендлер не сработает, т.к. он ждёт `GenerationStates.awaiting_photo`. Юзер видит тишину — приемлемо, т.к. у него есть кнопка Skip. |
| Юзер в `awaiting_feedback_text` жмёт `/start` | Стандартное поведение `/start` — сбрасывает FSM, начинает новую сессию. Фидбек теряется. |
| `last_photo_file_id` или `last_result_url` равен NULL при отправке админу | Логируем ошибку, отправляем админу только текстовое уведомление об оценке без фото. Не должно случаться в нормальном потоке. |
| Юзер удалил чат с ботом до того, как мы успеваем отредактировать сообщение с звёздочками | `try/except` вокруг `edit_text`, логируем ошибку. |
| Админ = сам юзер (ADMIN_ID совпадает с user_id) | Пропускаем отправку админу — не шлём себе же нотификации о своей оценке. |

## Проверяемость (вручную, тестов нет в проекте)

1. Запустить бота локально с тестовым `BOT_TOKEN` и `ADMIN_ID`.
2. От нового юзер-аккаунта: `/start` → выбор пола → выбор стиля → фото → дождаться результата → убедиться, что пришло второе сообщение со звёздами.
3. Тест 5 звёзд: нажать ⭐⭐⭐⭐⭐ → убедиться, что сообщение отредактировалось в "Рад, что понравилось" + кнопка рефералки → нажать кнопку → убедиться, что пришла ссылка.
4. Тест низкой оценки: повторить всё с нового аккаунта (БД reset), нажать ⭐⭐⭐ → убедиться, что админу пришли 2 фото + оценка → написать текст → убедиться, что админу пришёл третий месседж с текстом.
5. Тест Skip: с нового аккаунта, 2 звезды → Skip → убедиться, что админу только первый этап (оценка + фото).
6. Тест повторного показа: тем же аккаунтом сделать вторую генерацию → убедиться, что запрос оценки НЕ появляется.
7. Тест игнорирования: с нового аккаунта, получить запрос оценки, не кликать ничего, сделать вторую генерацию → убедиться, что запрос не появляется снова.
